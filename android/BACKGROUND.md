# 자동 장면 설명과 백그라운드 실행 · 0.5.0

1. 휴대폰을 ESP32-CAM Wi-Fi에 연결하고 앱 주소를 `http://192.168.4.1:81/stream`으로 둡니다. 크롬의 카메라 스트림 탭을 닫습니다.
2. **로컬 AI · 오프라인** 또는 **클라우드 AI · Gemini**를 선택합니다. Gemini는 본인 API 키와 인터넷 연결이 필요합니다.
3. 질문·언어·음성·분석 간격을 정합니다. HM-10도 사용할 경우 먼저 BLE 검색 → 모듈 선택 → 연결 → TEST 수신을 확인하고 새 물체 신호 체크박스를 켭니다.
4. **실시간 AI + 백그라운드 시작**을 누릅니다. 알림을 허용하면 실행 상태와 중지 버튼을 알림창에서 확인할 수 있습니다. 별도의 **ESP 영상 + YOLO 시작** 버튼은 누를 필요가 없습니다.
5. 앱을 벗어나거나 화면을 꺼도 서비스가 카메라·YOLO·장면 설명·선택한 BLE 연결을 소유합니다. 결과는 설치된 오프라인 TTS로 읽습니다. 앱에 돌아오면 최신 영상과 마지막 설명이 표시됩니다.
6. 앱의 **실시간 / 백그라운드 중지** 또는 실행 알림의 **중지**로 종료합니다. 긴 네이티브 연산 중이면 현재 연산을 마친 뒤 해제하므로 종료에 시간이 걸릴 수 있습니다.

## 처리 속도와 전환

YOLO 감지와 VLM 장면 설명의 처리 주기는 다릅니다. 영상은 계속 수신하고 YOLO는 가장 최근 대기 프레임을 감지합니다. VLM은 최소 시작 간격 3/5/10/20초(기본 5초)마다 새 프레임을 하나 선택합니다. 이전 분석이 끝나지 않았으면 다음 요청을 쌓지 않습니다. 예를 들어 분석에 12초가 걸리면 5초 설정이라도 5초마다 결과가 나오는 것은 아닙니다. 실제 수신 후 5초보다 오래된 입력은 새 분석에 사용하지 않습니다. 휴대폰 RAM·발열·통신 상태가 속도에 영향을 줍니다.

실행 중에도 로컬/Gemini를 바꿀 수 있습니다. 이전 모드의 진행 중 결과와 음성은 폐기하고, 취소 처리가 끝나면 최신 프레임으로 새 모드를 실행합니다. 로컬 네이티브 호출을 동시에 실행하거나 연산 중 다른 스레드에서 해제하지 않습니다. Gemini 선택 시 로컬 VLM 메모리를 해제합니다. 자동 실행 중 질문·간격·BLE 대상 변경은 중지 후 다시 시작합니다.

Gemini 자동 실행에서는 앱이 화면에 보이지 않을 때도 **사진·질문·활성화한 YOLO 관측을 Google에 반복 전송**합니다. 모바일 데이터와 API 요금이 계속 발생할 수 있습니다. 이미 서버로 보낸 요청의 처리나 비용까지 취소한다고 보장하지 않습니다. 모드나 키를 고르기만 해서는 전송하지 않지만, 실행 중 Gemini로 전환하면 자동 분석이 계속됩니다. 다른 공급자로 자동 전환하지 않습니다.

## 연결 끊김과 오류

카메라 오류는 5초 후 재연결합니다. 선택된 HM-10의 연결도 주기적으로 재시도하며, 전송 대기 명령은 재전송하지 않습니다. BLE 쓰기 완료는 아두이노 수신 ACK가 아닙니다. YOLO의 새 물체 이벤트만 기존 `OBSTACLE\n` 규칙에 따라 전송하며 VLM의 문장을 아두이노 명령으로 해석하지 않습니다.

Gemini 연결 오류·서버 오류는 최소 10초 뒤 최신 프레임으로 재시도합니다. 키·요청·할당량 오류 또는 로컬 AI 오류는 장면 설명을 일시 중지하고 안내합니다. 설정을 고치고 **장면 설명 재시도**를 누르거나 모드를 바꾸면 재개합니다. 이때 카메라·YOLO·BLE 감지는 계속됩니다. 끊긴 영상의 프레임을 반복 분석하지 않습니다.

## Android 실행 범위

사용자가 앱 화면에서 시작하는 foreground service이며 실행 알림, CPU wake lock, Wi-Fi lock을 사용합니다. 화면을 계속 켜 둘 필요는 없습니다. 알림 거부 시에도 Android가 서비스 실행을 허용할 수 있지만 알림창에서 중지 버튼이 보이지 않을 수 있으므로 앱으로 돌아와 중지하세요.

앱 강제 종료·휴대폰 재부팅 뒤 자동으로 카메라나 유료 API 요청을 재시작하지 않습니다. 시스템 메모리 회수·제조사 절전·사용자 강제 중지는 실행을 끝낼 수 있습니다. 휴대폰의 앱 배터리 설정이 백그라운드를 제한하면 해당 설정에서 허용해야 할 수 있습니다. 잠금 화면·장시간 실행·다른 앱 사용·ESP Wi-Fi/모바일 데이터 동시 연결·BLE는 실제 기기에서 확인해야 하며, 빌드와 JVM 테스트만으로 실물 동작을 보장하지 않습니다.
