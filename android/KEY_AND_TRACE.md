# API 키 붙여넣기와 상세 네이티브 기록 · 0.5.2

## 키 입력

0.5.1은 ASCII 영문·숫자·`_`·`-`, 길이 10~256에 맞지 않으면 모두 같은 ‘공백 없이 입력’ 문구를 표시했습니다. 실제 공백이 없더라도 허용 문자나 길이 때문에 같은 오류가 나올 수 있었습니다. 사용자가 붙여넣은 실제 키는 전달받지 않았고 내용을 확인하지 않았습니다.

0.5.2는 원본 입력에서 Unicode 공백/줄바꿈·NBSP·제로폭/BOM/방향 제어 같은 서식을 제거하고, 한 쌍의 외부 따옴표/백틱을 제거합니다. 실제 키에 들어 있는 영숫자나 기호를 다른 값으로 추측해 바꾸지 않습니다. HTTP 헤더에 들어갈 수 있는 출력 가능한 ASCII와 제한된 길이를 검사하고, 마스킹된 값·설정 코드·길이·그 밖의 문자 문제를 구분합니다. 키 값 자체는 오류 메시지나 로그에 넣지 않습니다.

저장했다고 Google이 유효한 키로 인증했다는 뜻은 아닙니다. 실제 인증·권한·할당량은 명시적 Gemini 요청에서 확인합니다. HTTP 요청 계층은 여전히 개행/제어 문자를 거부하고 고정 Google HTTPS 호스트에만 키를 헤더로 전송합니다. 보관 방식은 기존 Android Keystore AES-GCM이며 서버로 별도 저장하지 않습니다. 키 표시 체크박스는 사용자가 현재 입력 중인 값만 보여주고 저장된 키를 자동으로 표시하지 않습니다.

## 네이티브 기록

기존 오류 기록은 종료 이유·status만 읽고 네이티브 상세 추적을 읽지 않았습니다. Android 12 이상은 `ApplicationExitInfo.getTraceInputStream()`이 제공하는 AOSP tombstone protobuf에서 신호·abort 메시지·충돌 스레드의 backtrace와 라이브러리 이름을 읽습니다. 시스템이 제공하지 않거나 파일이 이미 삭제된 경우에는 읽을 수 없으며 ADB 수집이 필요합니다. 이전 앱 데이터/설치를 삭제하면 기록이 사라질 수 있습니다.

`NativeTombstone`은 입력 8MiB, 표시 길이·문자열·프레임 수를 제한하고 모르는 필드는 건너뜁니다. 메모리/레지스터/전체 로그 덤프는 복사하지 않습니다. 충돌 스레드 id가 맞는 스택만 선택하고, 맞는 스레드를 찾지 못하면 다른 스레드로 추측하지 않습니다. 이 코드는 원인 진단을 개선하며 SIGABRT 자체를 고쳤다는 의미는 아닙니다.

## 검사 범위

개발 환경에서 가짜 키와 합성 tombstone만 사용한 로컬 JVM 검사 32개가 통과했습니다. Unicode 붙여넣기·키 헤더의 정확한 전송·헤더 삽입 거부·이유별 오류, protobuf 필드 순서·충돌 스레드 선택·범위/크기 제한·잘린 값·gzip·텍스트 대체 형식을 다룹니다. 실제 사용자 키를 사용하거나 출력하지 않았습니다. 실제 Samsung 기기의 입력기·Keystore·tombstone 제공 여부는 이 시험으로 확인되지 않습니다.

모델을 내장한 Android 빌드·전체 테스트·Lint는 공개 배포 작업에서 검사하며 실제 배포 APK의 검증 결과를 확인한 뒤 추가 기록합니다. 기존 네이티브 종료 증상과 ESP 타임아웃은 별도로 상세 로그를 확보해 조사 중입니다.
