말소리로 자동 중단하는 기능과 무음 후 자동 전송을 제거했습니다. 답변이 끝나면 마이크를 닫고 다음 버튼을 기다립니다. 녹음은 최대 60초이며 한도에 도달해도 버튼을 눌러야 전송합니다. 앱·알림 버튼의 문구는 녹음/전송/답변 상태에 따라 바뀝니다. 전화 확인도 답변 후 다음 버튼 녹음에서 이어집니다.

**UNO 정식 v5의 `ASSIST` 신호를 그대로 사용합니다.** 물리 버튼은 어시스턴트만 호출하고, 모터는 앱 TEST·AI 위험 신호로 동작합니다. UNO를 다시 올리기 전에 현재 코드가 정식 v5인지 확인하세요. `BUTTON: local servo test`는 임시 모터 점검 코드의 출력입니다.

**0.8.2 · 흰지팡이 보행 상황 판단 / 이미지 GPU / 한국어 / 음성 대체**

YOLO의 ‘화면 어디 감지’ 음성을 제거했습니다. Gemini는 이전·최신 사진을 계속 비교하되 같은 상황에는 조용히 있고, 보행에 필요한 새 방해물이나 사진에서 분명히 악화된 상황만 자연스럽게 안내합니다. 지팡이 좌우 움직임·잠깐의 소실·의자 개수 변동을 유지된 같은 상황으로 취급합니다. 상단 영상도 보지만 실제 머리 높이·2~3m 거리를 측정했다고 말하지 않습니다.

Gemini 안내는 기존 ElevenLabs 여자(기본)/남자 음성입니다. YOLO 알림이 ElevenLabs 재생을 끊던 코드를 제거했고, 실패·지연·재생 오류에는 현재 안내를 기본 한국어 음성으로 한 번 대체합니다. 로컬 AI는 휴대폰 기본 한국어 TTS만 사용합니다. 사용자 중지·지난 장면에는 대체 음성도 내지 않습니다. 자동 분석은 기본 2초 최소 간격이며 이전 작업이 끝나야 다음 작업을 시작합니다.

로컬은 유지하며 이미지 병목에 선택형 Vulkan GPU 가속과 CPU 대체·복구를 추가했습니다. **기기에서 40초가 얼마나 줄었는지와 2초 이하 달성은 아직 미측정**입니다. 영어 기본값을 한국어로 고치고, 필요한 경우 최초 인터넷으로 준비한 기기 내 번역 모델로 영어 문장만 한국어로 바꿉니다. 오래된 로컬 결과는 실시간 보행 음성으로 읽지 않습니다.

[상세 사용법·거리/정확도/속도 제한과 검증](https://github.com/Siroko-0516/new_orphan/blob/main/android/WALKING_GUIDANCE.md). 실제 거리·진행 방향 센서가 없으므로 정확한 2~3m 안내나 모든 장애물 탐지를 보장하지 않습니다. 개인 Gemini·ElevenLabs 키는 앱 설정에 입력하고, 번역이 필요하면 ‘오프라인 한국어 번역 준비’를 누릅니다. 공개 0.7.0과 서명이 달라 기존 앱을 삭제한 후 설치해야 합니다. 삭제하면 키·설정·준비된 모델이 초기화됩니다.

**0.7.0 · 변화가 있을 때만 안내 / 로컬 CPU 가속 / Gemini ElevenLabs 음성**

자동 실행은 시작 시 한 번, 이후 큰 장면 변화가 확인될 때 AI로 설명합니다. 새 장애물은 YOLO가 여러 프레임에서 확인하면 짧게 안내합니다. 같은 장면·일시적 흔들림·한 장면의 여러 물체를 계속 읽는 현상을 줄이고, 분석 중 장면이 달라지면 늦은 AI 설명은 음성으로 읽지 않습니다. 단색·너무 어둡거나 밝은 영상은 AI 추론을 생략하고 ‘확인하기 어렵다’고 표시합니다. 보행·지팡이 성능에 관한 근거 없는 일반론을 제한합니다. 모든 오인식이 제거됐다는 보장은 아닙니다.

**0.5.3 · 확인된 MiniCPM 네이티브 종료 원인 수정**

상세 종료 스택에서 `LocalVlm → processSystemPrompt → common_chat_format_single`의 `std::invalid_argument: Unable to generate parser for this template`가 JNI 밖으로 빠져나가 SIGABRT를 일으킨 것을 확인했습니다. MiniCPM-V 4.7 템플릿은 사용자 질문을 포함한 대화를 요구하는데, 기존 코드는 시스템 문장만 먼저 렌더링했습니다.

이번 버전은 **시스템 지시·사진·질문을 포함한 전체 대화를 한 번에 렌더링·평가**하고, 텍스트 프롬프트에 불필요한 응답 파서 자동 생성을 사용하지 않습니다. 모델의 원래 Jinja 템플릿과 assistant 시작 문구를 유지합니다. 모든 JNI 진입점에서 C++ 예외를 Java 오류로 전달하고 JNI 문자열/이미지 버퍼는 예외가 나도 해제합니다. 실패가 생기면 앱 전체 종료 대신 기록·안내할 수 있게 합니다. 이 처리가 모든 종류의 네이티브 신호·시스템 강제 종료를 막는다는 뜻은 아닙니다.

실제 내장 언어 모델로 이전 템플릿 오류 재현과 수정 경로 검사를, JNI 예외 변환 검사를 수행합니다. Android 기기의 완전한 실행·속도는 기기에서 별도 확인이 필요합니다. ESP 영상 15초 수신 타임아웃은 별도로 기록되는 연결 문제이며 이 템플릿 수정만으로 ESP 통신 문제가 해결됐다고 보장하지 않습니다.

API 키 붙여넣기와 상세 네이티브 기록 개선도 함께 포함합니다.

**0.5.2 · API 키 붙여넣기와 네이티브 상세 기록 개선**

기존 앱은 API 키 입력의 길이·허용 문자 검사에 실패하면 원인에 관계없이 같은 ‘공백 없이 입력’ 문구를 표시했습니다. 이는 Google의 인증 결과가 아닌 앱 자체 입력 검사였습니다.

이번 버전은 붙여넣기의 공백·줄바꿈·NBSP·제로폭/방향 서식 문자를 정리하고, 키를 감싼 한 쌍의 따옴표/백틱을 제거합니다. 키 알파벳에 대한 불필요한 제한을 줄이고 HTTP 헤더로 보낼 수 있는 ASCII 값인지 검사합니다. 가려진 키·설정 코드 전체·길이·비ASCII 문자 문제는 각각 다르게 안내하며 키 값은 오류 문구에 넣지 않습니다. **입력한 키 표시**를 선택해 이 기기에서 새 입력만 확인할 수도 있습니다. 키 저장은 실제 Google 인증 성공을 뜻하지 않으며 인증·할당량·권한은 Gemini 요청에서 확인됩니다. API 키는 채팅에 보내지 마세요.

**앱 오류 기록 보기 · 복사**는 Android 12 이상에서 시스템이 제공한 네이티브 tombstone의 `Abort message`, 충돌 스레드, 호출 스택과 라이브러리 이름도 읽습니다. 메모리 덤프·전체 로그는 복사하지 않으며 기록을 자동 전송하지 않습니다. 시스템이 상세 파일을 제공하지 않으면 PC의 ADB 로그를 이용해야 합니다. 0.5.2 단계의 기록 조회 개선은 진단 기능이며, 확인된 템플릿 종료 원인 수정은 위의 0.5.3 변경입니다.

**0.5.1 · ESP 영상/YOLO 실행 중 종료 오류 대응**

영상이 나오다가 앱이 종료되는 문제를 조사하면서, 화면 렌더러가 아직 사용할 수 있는 이전 프레임을 즉시 `recycle()`하던 코드를 수정했습니다. YOLO의 416×416 입력 이미지·픽셀 배열·직접 버퍼·입력 텐서를 재사용해 프레임마다 큰 메모리를 새로 할당하던 부분을 줄였습니다. 입력 해상도·감지 임계값·클래스는 유지합니다.

Java 메모리 부족과 실행 라이브러리 로딩 오류는 스트림을 중지하고 안내하며, 같은 오류를 5초마다 재연결하지 않습니다. **앱 오류 기록 보기 · 복사**에서 앱의 마지막 Java 오류와 Android 11 이상이 기록한 종료 이유(메모리 부족/Java/네이티브 오류 등)를 확인할 수 있습니다. 기록은 앱 내부에만 보관하고 자동 전송하지 않습니다.

사용자의 실제 기기 오류 스택을 아직 받지 못했으므로 이번 수정으로 해당 기기의 모든 종료 원인이 해결됐다고 확정하지 않습니다. 새 버전에서도 종료되면 앱을 다시 열어 오류 기록을 복사해 알려주세요. 기존 버전은 Java 오류 저장 기능이 없었고, 삭제·재설치하면 이전 기록이 없어질 수 있습니다.

ESP32 카메라 영상 → 휴대폰 YOLO 감지와 로컬 AI / Gemini 반복 장면 설명, 화면 밖 실행, HM-10 BLE 알림을 추가한 Android 8 이상 ARM64 테스트 앱입니다.

**자동 분석·백그라운드 사용법**

1. **영상 입력 선택**에서 휴대폰 후면·전면을 선택합니다. ESP를 사용한다면 ESP32-CAM을 선택하고 Wi-Fi에 연결해 주소 `http://192.168.4.1:81/stream`을 사용합니다. 브라우저 카메라 탭은 닫습니다.
2. 앱 상단에서 **로컬 AI · 오프라인** 또는 **클라우드 AI · Gemini**를 선택합니다. 질문·언어·음성과 최소 분석 시작 간격(기본 5초)을 정합니다.
3. **실시간 AI + 백그라운드 시작**을 누릅니다. 카메라·YOLO·선택한 AI가 실행되고, 화면을 벗어나거나 꺼도 서비스가 처리를 이어갑니다. 앱에 돌아오면 최신 프레임과 마지막 설명이 표시됩니다.
4. 앱의 **실시간 / 백그라운드 중지** 또는 실행 알림의 **중지**로 종료합니다. 긴 로컬 연산은 완료 뒤 해제하므로 중지 처리에 시간이 걸릴 수 있습니다.

한 번에 장면 설명 하나만 처리하며 요청을 쌓지 않습니다. 이전 분석이 끝난 뒤 최신 프레임을 고르므로 **5초 설정은 5초마다 답변 완료를 보장하지 않습니다.** 실행 중 로컬/Gemini를 바꾸면 이전 결과를 폐기하고 새 모드로 계속 분석합니다. 수동 사진 한 장 분석과 YOLO 전용 버튼도 남아 있습니다.

로컬 MiniCPM 언어 모델 Q4_K_M과 해당 비전 mmproj가 APK에 함께 들어 있습니다. 별도 모델 다운로드·선택이나 API 키 없이 앱 내부에서 준비·실행합니다. 한국어 설명은 실험적이며 언어 혼합이 있을 수 있습니다. 설치 파일은 약 1.8GB이고 첫 AI 준비에 내부 저장 공간 약 1.8GB가 추가로 필요하므로 여유 공간 6GB 이상을 권장합니다.

Gemini는 **Gemini API 키 · 모델 설정**에 본인 키를 입력합니다. 기본 모델은 `gemini-3.1-flash-lite`입니다. 자동 실행 중에는 화면이 꺼져 있어도 사진·질문·활성화한 YOLO 관측을 Google로 반복 전송하며 데이터·API 요금이 발생할 수 있습니다. ESP Wi-Fi를 유지하면서 인터넷도 쓰려면 모바일 데이터 등 별도 연결이 필요합니다. 키는 Android Keystore로 암호화해 저장하고 APK에 공유 키를 넣지 않습니다. 중지 상태에서 모드만 고르면 전송하지 않으며, 자동 실행 중 Gemini로 전환하면 반복 전송합니다. 다른 공급자로 자동 전환하지 않습니다.

HM-10은 실행 전에 검색·선택·연결·TEST 수신을 확인하고 **새 물체 감지 시 아두이노 신호 전송**을 켭니다. 서비스가 선택한 기기로 재연결하며 YOLO 새 물체 이벤트에 `OBSTACLE\n`을 전송합니다. BLE 쓰기 완료는 보드의 수신 ACK가 아닙니다.

카메라 오류는 5초 후 재연결, Gemini 연결·서버 오류는 최소 10초 후 새 프레임으로 재시도합니다. 키·할당량·요청 오류 또는 로컬 AI 오류는 장면 설명을 일시 중지합니다. 설정을 고치고 **장면 설명 재시도**를 누르세요. 카메라·YOLO·BLE는 계속됩니다.

- 디버그 서명이 다른 APK로 설치할 때는 기존 길잡이를 삭제한 후 설치해야 합니다. 디버그 서명은 배포 태그 간 동일함을 보장하지 않습니다. 삭제하면 개인 설정·저장한 API 키·준비된 모델 복사본이 삭제됩니다. 내장 모델은 첫 준비에서 다시 복사됩니다.
- 백그라운드 실행 알림을 허용하면 중지 버튼을 알림창에서 사용할 수 있습니다. 앱 강제 중지·재부팅 뒤 자동 재시작하지 않습니다. 제조사 절전·메모리 회수로 서비스가 종료될 수 있습니다.
- 빌드·Lint·JVM 테스트와 파일 무결성 검증은 실제 Android의 화면 끄기·장시간 실행·RAM·발열·네트워크·BLE·TTS 검증을 대신하지 않습니다. 실기기 동작과 속도는 별도 확인이 필요합니다.
- 어느 모드든 설명이 부정확할 수 있으며 거리·충돌 위험을 측정하지 않습니다. 음성은 휴대폰에 설치된 해당 언어의 오프라인 음성을 사용합니다.

사용법·구현과 검증 범위는 저장소의 `android/BACKGROUND.md`, `android/AI_MODES.md`와 `android/BACKGROUND_VALIDATION.md`에 기록합니다. 소스·가중치 출처와 라이선스는 저장소 및 APK의 assets에 포함합니다.
