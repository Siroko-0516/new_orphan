# 길잡이 Android · 로컬 VLM 시제품

현재 앱은 **GGUF 언어 모델 + 대응하는 비전 파일 가져오기 → 사진 촬영/선택 또는 ESP32 JPEG 한 장 → 선택적 YOLO 보조 감지 → MiniCPM 로컬 분석 → 기기의 오프라인 TTS**를 구현합니다. 기존 웹 앱과 별도 프로젝트입니다.

이 버전에는 **YOLO 실시간 감지, MJPEG 연속 미리보기, Gemini/GPT, ElevenLabs, 별도 Supertonic 모델이 포함돼 있지 않습니다.** YOLO는 사진 분석을 누를 때만 같은 사진에서 물체·정규화 좌표를 감지하고 MiniCPM에 보조 정보로 전달합니다. 두 모델을 순차 실행하고 메모리는 함께 유지하며, YOLO를 끄면 추가 세션을 만들지 않습니다. 먼저 실제 기기에서 로컬 VLM의 동작·메모리·설명 품질을 검증하는 설치형 앱입니다. 영어를 기본으로 두며 한국어는 실험적입니다. MiniCPM 4.7 1B의 한국어 혼합 현상을 앱이 자동으로 고쳐주지는 않습니다.

## 기기에서 사용

1. Android 8 이상, **arm64-v8a** 기기에 APK를 설치합니다. 디버그 APK는 테스트용입니다. 학교가 관리하는 기기는 담당자에게 설치 허용을 받아야 하며 설치 제한 우회 기능은 없습니다.
2. 받은 `MiniCPM-V-4_7-1B-Q4_K_M.gguf`를 **언어 모델 선택**에서 선택합니다.
3. 같은 모델용 `mmproj-model-f16.gguf`를 **비전 파일 선택**에서 선택합니다. 파일명만 같다고 다른 모델의 비전 파일을 섞어 쓰면 안 됩니다.
4. 파일은 앱 내부 저장소에 복사합니다. 원본 파일에 더해 약 1.8GB의 추가 공간이 필요합니다. 언어 모델과 비전 모델을 교체할 때마다 기존 로딩은 해제합니다.
5. **모델 불러오기**를 누른 뒤 사진을 선택하거나 기본 카메라 앱으로 촬영합니다. 사진은 방향 정보를 적용하고 최대 768px로 축소해 처리합니다. 한 번에 한 장만 분석합니다.
6. 질문을 입력하고 **기기에서 사진 분석**을 누릅니다. 출력과 분석 완료 시간을 확인합니다. 준비된 모델은 다음 분석에 재사용하고, 매 사진마다 문맥을 새로 만듭니다.
7. **오프라인 한국어 음성 시험**으로 설치된 음성을 확인합니다. 설치된 TTS 엔진에서 네트워크가 필요 없는 해당 언어 음성만 선택합니다. 없으면 모델 답변은 표시하고 음성을 설치하라는 상태를 보여줍니다. OS 엔진 자체는 별도 구성 요소입니다.

중지는 Java 작업·토큰 사이에서 확인하므로 긴 이미지 인코딩·모델 로딩이 즉시 끊기는 것은 아닙니다. 네이티브 sampler를 다른 스레드에서 해제하는 위험한 취소 방식은 쓰지 않습니다. 화면을 벗어나면 추가 생성·자동 음성을 중지 요청합니다. 모델 메모리 해제 버튼은 현재 작업이 끝난 뒤 사용할 수 있습니다.

모델 추론에는 서버·API 키가 필요하지 않습니다. 사진과 답변을 서버로 보내지 않습니다. 인터넷 권한은 선택적 ESP32 로컬 사진 수신에 사용하며, 구현상 HTTP/HTTPS의 **사설 IPv4 리터럴 주소**만 허용하고 리다이렉트를 따르지 않습니다. HTTPS는 인증서 검증을 유지합니다.

## ESP32 연결

같은 Wi-Fi 또는 보드의 AP에 연결한 후 `http://192.168.4.1/capture`처럼 JPEG를 반환하는 주소를 입력합니다. `/stream`이 MJPEG를 반환하면 첫 JPEG 프레임 하나를 추출하고 연결을 닫습니다. 최대 응답 2MB, 연결/읽기 각각 8초 제한이며 자동 재접속·지속 스트리밍은 이 버전에 없습니다. 캡처 주소는 보드 펌웨어에 따라 다릅니다. 실제 보드에서 확인해야 합니다.

## Android Studio에서 빌드

필요 항목: JDK 17 이상(21 권장), Python 3, Android SDK 35, Build Tools 35.0.0, NDK **27.0.12077973**, CMake **3.22.1**. Android Studio의 SDK Manager에서 설치할 수 있습니다.

```bash
cd android
python scripts/prepare_engine.py
# Android Studio에서 이 android 폴더를 열고 SDK 경로를 지정
# 또는 ANDROID_HOME 설정 후:
./gradlew :app:assembleDebug :app:testDebugUnitTest
```

Windows CMD:

Windows에서는 소스 폴더를 `C:\giljabi`처럼 짧은 경로에 두면 네이티브 빌드의 긴 경로 문제를 줄일 수 있습니다.

```bat
cd android
python scripts\prepare_engine.py
gradlew.bat :app:assembleDebug :app:testDebugUnitTest
```

출력: `app/build/outputs/apk/debug/app-debug.apk`. 기기에 `adb install -r app-debug.apk`로 설치하거나 파일을 전달해 설치합니다. 스토어 배포용 서명은 별도로 준비해야 합니다. 다른 환경에서 새로 빌드한 디버그 APK는 서명 키가 달라 기존 앱을 업데이트하지 못할 수 있습니다. 개발 도구·의존성 최초 다운로드에는 인터넷이 필요하지만 완성된 앱은 모델 파일과 오프라인 음성 준비 후 사진 분석을 오프라인으로 실행하도록 구성했습니다.

Gradle·네이티브 엔진은 체크섬과 버전이 고정됩니다. 원본 엔진 폴더를 수정한 경우 준비 스크립트가 덮어쓰지 않습니다. 다른 엔진 버전을 섞지 말고 `third_party/NOTICE.md`의 고정 커밋을 확인하세요.

## 검증 범위

이 환경에서 ARM64 APK 빌드, APK 서명 검증, 네이티브 라이브러리 의존성 포함 검사, APK 내 YOLO 모델의 원본 해시 일치를 확인했습니다. JVM 테스트 6개가 통과했습니다: 로컬 카메라 IP 제한, JPEG/MJPEG 경계·잘린 프레임·응답 크기 제한, YOLO letterbox 좌표 복원·클래스별 NMS. **실제 기기의 카메라·ONNX 추론·MiniCPM 추론·오프라인 TTS·ESP32 연결은 APK 빌드만으로 검증되지 않습니다.** A52s나 Tab S9 FE+의 실행 RAM·속도는 실제 기기에서 측정해야 합니다.

앱은 보조 안내용이며 위험 감지나 안전을 보장하지 않습니다. 이 앱 버전의 분석 답변이 자연스러워도 없는 물체·움직임을 만들어내는지 직접 비교해야 합니다.

## 라이선스

Android 앱의 새 소스는 AGPL-3.0에 따라 제공하며, MIT 코드와 제3자 구성 요소는 각 라이선스를 유지합니다. 공식 JNI 코드와 엔진의 출처는 `third_party/NOTICE.md`, 라이선스는 앱의 `assets/licenses/`에 있습니다. YOLO 모델은 APK에 포함되며 Ultralytics AGPL-3.0 / Enterprise 조건을 확인해야 합니다. MiniCPM 언어·비전 파일은 포함하지 않으며 사용·배포 시 모델별 라이선스가 적용됩니다. 공식 앱의 Kotlin UI·모델 자동 다운로드·기존 앱의 서명 키는 사용하지 않습니다.
