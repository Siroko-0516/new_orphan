# 길잡이 Android · ESP 실시간 YOLO + 로컬 VLM

최신 **0.4.0-full**은 앱 상단에서 **로컬 AI / Gemini**를 고릅니다. 로컬 모델 두 파일이 APK에 들어 있고, Gemini는 개인 API 키를 앱에 설정해 사용합니다. [두 모드 사용 안내](AI_MODES.md) · [모델 내장 빌드](MODEL_BUNDLE.md) · [다운로드](../downloads/README.md).

앱은 **ESP32 MJPEG 수신 → 기기 내 YOLO 감지 박스**, **현재 장면 또는 선택한 사진 → 선택한 AI의 설명 → 오프라인 TTS**, **HM-10 BLE → 아두이노 TEST / 새 물체 신호**를 구현합니다. YOLO만 쓸 때는 VLM을 불러올 필요가 없습니다. 기존 웹 앱과 별도 프로젝트입니다.

이 버전에는 **GPT, ElevenLabs, 별도 Supertonic, 휴대폰 카메라 연속 감지, AI 자동 반복 설명**은 포함하지 않습니다. ESP 수신기는 MJPEG를 계속 읽되 감지기는 가장 최근 대기 프레임만 처리합니다. 영상/박스는 YOLO 처리 결과에 맞춰 갱신하므로 원본 카메라 FPS와 화면 갱신 속도는 다를 수 있습니다. 분석 버튼을 누른 시점의 사진과 YOLO 관측을 고정해 선택한 AI로 분석합니다. YOLO는 별도 작업 스레드에서 계속 실행되지만 CPU·메모리를 공유하므로 실제 성능을 기기에서 확인해야 합니다. MiniCPM 4.7 1B의 한국어 혼합 현상을 이 UI가 자동으로 고쳐주지는 않습니다.

## ESP 영상과 YOLO 먼저 사용

1. 휴대폰을 ESP32-CAM이 만든 Wi-Fi에 연결하고 인터넷이 없어도 연결을 유지합니다.
2. 앱의 주소를 `http://192.168.4.1:81/stream`으로 두고 **ESP 영상 + YOLO 시작**을 누릅니다. 주소는 펌웨어에 맞게 바꿀 수 있습니다.
3. 영상에 감지 박스, 수신 FPS, YOLO 처리 시간이 표시됩니다. 원본 브라우저 스트림 탭은 닫아 두세요. 보드의 스트림 동시 접속 처리에 제한이 있을 수 있습니다.
4. **ESP 영상 중지**를 누르면 마지막 사진은 남아 로컬 AI로 설명할 수 있습니다.

최신 소스는 카메라 대상 서브넷에 맞는 Wi-Fi를 선택하고 로컬 IP와 연결 단계를 표시합니다. 공개 호스트·도메인 이름·리다이렉트는 허용하지 않고 사설 IPv4 주소만 받습니다. 연결 10초·읽기 15초, 프레임당 최대 2MB 제한이 있습니다. `/capture`는 사진용이므로 실시간 시작에서 거부합니다. 자동 재접속은 하지 않습니다. **ESP 연결 진단**은 사진 응답과 영상의 첫 프레임을 별도로 검사합니다. 중지 시 응답 헤더를 기다리는 연결도 닫습니다. 이 앱 변경은 브라우저에서도 느린 ESP 무선 전송 자체를 해결하지 않습니다.

## 기기에서 사용

1. Android 8 이상 **arm64-v8a** 기기에 full APK를 설치합니다. 약 1.8GB 설치 파일과 첫 모델 준비에 필요한 공간을 고려해 내부 여유 저장 공간 6GB 이상을 권장합니다.
2. 상단에서 **로컬 AI · 오프라인** 또는 **클라우드 AI · Gemini**를 선택합니다. Gemini는 **Gemini API 키 · 모델 설정**에서 개인 키를 입력합니다. 기본 모델은 `gemini-3.1-flash-lite`입니다.
3. ESP 영상을 받거나 **사진 선택 / 카메라 촬영**으로 사진을 준비합니다. 사진 방향을 적용하고 최대 768px로 축소합니다.
4. 질문과 언어를 정한 뒤 선택한 모드의 분석 버튼을 누릅니다. 로컬 full 버전은 모델 선택 없이 내장 모델을 준비합니다. Gemini는 인터넷을 통해 선택한 사진·질문·YOLO 보조 관측을 Google에 전송합니다.
5. **오프라인 한국어 음성 시험**으로 설치된 음성을 확인합니다. 네트워크가 필요 없는 해당 언어 음성만 선택하며, 음성이 없으면 화면 결과와 음성 준비 안내를 표시합니다.

이전 앱이나 직접 빌드한 lite 버전에서 로컬 VLM을 쓰려면 해당 언어 GGUF와 같은 모델용 mmproj를 선택해 앱 내부에 복사해야 합니다. full 버전에는 이 두 파일이 이미 들어 있습니다. 파일명만 같은 다른 모델의 mmproj를 섞으면 안 됩니다.

중지는 Java 작업·토큰 사이에서 확인하므로 긴 이미지 인코딩·모델 로딩이 즉시 끊기는 것은 아닙니다. 네이티브 sampler를 다른 스레드에서 해제하는 위험한 취소 방식은 쓰지 않습니다. 화면을 벗어나면 추가 생성·자동 음성을 중지 요청합니다. 모델 메모리 해제 버튼은 현재 작업이 끝난 뒤 사용할 수 있습니다.

로컬 모드는 서버·API 키가 필요 없고 사진과 답변을 서버로 보내지 않습니다. Gemini 모드는 인터넷·개인 API 키가 필요하고 Google에 분석 자료를 전송합니다. 카메라는 로컬 Wi-Fi, Gemini는 인터넷 경로로 연결하며 HTTPS 인증서 검증을 유지합니다. 화면을 벗어나면 스트림과 BLE 연결을 종료하고 AI 요청·TTS를 중지 요청합니다. 백그라운드 수신은 지원하지 않습니다. 키 저장과 동시 네트워크의 상세 범위는 [두 모드 안내](AI_MODES.md)를 참고하세요.

## HM-10 / 아두이노 연결

1. **BLE 기기 검색**을 누르고 주변 기기 권한(Android 11 이하는 위치 권한 및 위치 서비스)을 허용합니다.
2. 목록에서 해당 HM-10을 선택하고 **선택한 BLE 기기 연결**을 누릅니다. 기본 서비스 FFE0 / 쓰기 characteristic FFE1이며 다른 모듈은 **BLE UUID 설정**에서 실제 값을 입력합니다.
3. 먼저 **아두이노 TEST 신호 보내기**를 눌러 수신을 확인합니다. [아두이노 수신 코드와 배선](../arduino/hm10_receiver/README.md)을 참고하세요.
4. ESP 감지 실행 중 **새 물체 감지 시 아두이노 신호 전송**을 켜면 새 물체 이벤트에 `OBSTACLE\n`을 씁니다. 처음에는 이 체크박스가 꺼져 있습니다.

새 물체 이벤트는 화면 중앙/아래쪽의 일정 크기 이상 사물 일부를 대상으로, 감지 3프레임 연속 확인·같은 종류 박스의 겹침 추적·최소 2초 신호 간격을 사용합니다. 잠깐 가려진 같은 물체는 재알림하지 않고 3초 이상 놓치면 새로 추적합니다. 연결·설정 전환 때도 새로 확인합니다. 이 규칙은 물체 감지 알림일 뿐, 실제 보행 경로·거리·접근·충돌 위험을 확정하지 않습니다.

명령은 한 줄 ASCII이며 큐는 최대 4개, 한 번에 한 번만 GATT 쓰기를 진행합니다. 연결 종료 시 대기 명령을 버리고 자동 재전송하지 않습니다. 앱의 `BLE 쓰기 완료`는 아두이노 수신 확인이 아니므로 보드의 USB 시리얼/LED로 확인해야 합니다. Bluetooth Classic HC-05/HC-06은 이 BLE 구현 대상이 아닙니다.

## Android Studio에서 빌드

필요 항목: JDK 17 이상(21 권장), Python 3, Android SDK 35, Build Tools 35.0.0, NDK **27.0.12077973**, CMake **3.22.1**. Android Studio의 SDK Manager에서 설치할 수 있습니다.

```bash
cd android
python scripts/prepare_engine.py
# Android Studio에서 이 android 폴더를 열고 SDK 경로를 지정
# 또는 ANDROID_HOME 설정 후:
./gradlew :app:assembleDebug :app:testDebugUnitTest
```

Windows CMD:

Windows에서는 소스 폴더를 `C:\giljabi`처럼 짧은 경로에 두면 네이티브 빌드의 긴 경로 문제를 줄일 수 있습니다.

```bat
cd android
python scripts\prepare_engine.py
gradlew.bat :app:assembleDebug :app:testDebugUnitTest
```

출력: `app/build/outputs/apk/debug/app-debug.apk`. 기기에 `adb install -r app-debug.apk`로 설치하거나 파일을 전달해 설치합니다. 스토어 배포용 서명은 별도로 준비해야 합니다. 배포한 0.1.0과 0.2.0은 디버그 서명이 다르므로 기존 0.1.0 삭제 후 새 앱을 설치해야 합니다. 삭제 시 앱 내부 모델 복사본도 삭제되어 원본을 다시 선택해야 합니다. 개발 도구·의존성 최초 다운로드에는 인터넷이 필요하지만 완성된 앱은 모델 파일과 오프라인 음성 준비 후 분석을 오프라인으로 실행하도록 구성했습니다.

Gradle·네이티브 엔진은 체크섬과 버전이 고정됩니다. 원본 엔진 폴더를 수정한 경우 준비 스크립트가 덮어쓰지 않습니다. 다른 엔진 버전을 섞지 말고 `third_party/NOTICE.md`의 고정 커밋을 확인하세요.

## 검증 범위

ARM64 빌드·서명·Lint·JVM 테스트 결과는 배포 APK와 함께 기록합니다. 테스트는 사설 IP 제한, 연속 MJPEG 프레임 보존·잘린/과대 프레임, YOLO 좌표/NMS, 새 물체 확인·누락·중복 억제·재연결·알림 간격을 다룹니다. **실제 기기의 ONNX/MiniCPM 추론·TTS·ESP32 수신·HM-10 송신·아두이노 수신은 빌드와 JVM 테스트만으로 검증되지 않습니다.** A52s나 Tab S9 FE+의 실행 RAM·속도는 실제 기기에서 측정해야 합니다.

앱은 보조 안내용이며 위험 감지나 안전을 보장하지 않습니다. 이 앱 버전의 분석 답변이 자연스러워도 없는 물체·움직임을 만들어내는지 직접 비교해야 합니다.

## 라이선스

Android 앱의 새 소스는 AGPL-3.0에 따라 제공하며, MIT 코드와 제3자 구성 요소는 각 라이선스를 유지합니다. 공식 JNI 코드와 엔진의 출처는 `third_party/NOTICE.md`, 라이선스는 앱의 `assets/licenses/`에 있습니다. YOLO 모델은 APK에 포함되며 Ultralytics AGPL-3.0 / Enterprise 조건을 확인해야 합니다. 0.2.0까지의 공개 APK와 경량 빌드는 MiniCPM 언어·비전 파일을 포함하지 않습니다. full 빌드는 실제 가중치와 해당 게시자의 모델 라이선스를 함께 포함합니다. Gemini는 외부 API 서비스이며 APK에 그 모델 가중치를 넣지 않습니다. 공식 앱의 Kotlin UI·모델 자동 다운로드·기존 앱의 서명 키는 사용하지 않습니다.
